# SmartCommute — automated features

Jobs the system now does by itself instead of waiting for someone to do them by hand. Each one is scheduled or triggered by the app. Behaviour is described in more detail in the use case narratives named in the last column.

## Notes

- **The scheduler must be running.** Items 1, 5, 9, 11, 15, 16, 18 and 19 only run if `php artisan schedule:run` is called every minute from a cron entry (or a worker) on the host.
- **The seeded fines are indicative.** Overcharging (₱5,000 / 10,000 / 15,000), colorum 1st offense (₱50,000) and the franchise-condition tiers follow LTFRB/DOTr-LTO Joint Administrative Order 2014-01. Sources disagree on the other amounts, so check them against current LTFRB/LTO issuances. The Driver Manager can edit any of them under Violation Codes.
- **Seeding the codes is destructive.** Running `ViolationCodeSeeder` removes every existing violation code, and the violation logs that belong to them.
- **Auto-closed hours are an estimate.** Nobody knows when the driver really stopped, so the entry carries the credited regular shift. "Mark reviewed" only acknowledges it; hours can't be edited yet.
- **The inactivity check never suspends a driver who has not been warned.** A driver found already past a week with no warning on file gets the warning first and is suspended on a later run. Set `HR_EMAIL` so the warning names an address; without it the email just says "HR". An admin or Driver Manager reactivating a driver restarts their inactivity clock.
- **Maintenance km alerts use logged readings.** There is no live odometer, so a vehicle's current reading is the highest odometer logged for any of its services. Tasks with no interval are never due.
- **Top-ups have nothing to reconcile.** A wallet top-up is credited the moment it is confirmed (there is no gateway for top-ups yet), so it cannot be left pending. It gets an emailed receipt; reconciliation, failure alerts and failed-payment emails apply to **fare** payments through GCash and Maya.
- **Emails go out through the mail settings in `.env`.** Every notification passes through `Notifier`, which logs and skips a failed send. To add an in-app list or push/SMS later, add the channel to `NOTIFICATION_CHANNELS` and a `toX()` method to the notifications.
- **The on-board check relies on drivers' phones broadcasting.** That is why it is off by default; turn it on once drivers broadcast reliably. A commuter who refuses location access cannot pay while it is on.
- **Distance is recorded from now on.** The GPS trail used to store 0 for every ping; it now stores the kilometres since the previous ping (a gap over 10 minutes or a jump over 20 km counts as 0). Older history shows 0 km.
- **Flags are once per window.** The repeat-violator and fare-evasion jobs look in the audit trail for an earlier flag of the same driver or commuter inside the window, so a daily run does not repeat itself.
- **A replacement fully takes over the seat.** A vehicle that had two drivers gets two again (the new driver and the one who stayed, taking turns, the one who stayed first); a single-driver vehicle gets one. A vehicle that is no longer Active, or that the Maintenance Manager already staffed by hand, has its vacancy closed as "not needed" instead.
- **An expired licence takes the driver off their vehicle, not off the system.** They keep their account and are emailed; the Maintenance Manager reassigns them after the licence is renewed. Set `RELEASE_EXPIRED_LICENCE_DRIVERS=false` to turn that off. With `AUTO_REPLACE_DRIVERS=false` the system only reports the vacancy and suggests the best free drivers.
