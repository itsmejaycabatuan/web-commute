# SmartCommute — automated features

Jobs the system now does by itself instead of waiting for someone to do them by hand. Each one is scheduled or triggered by the app. Behaviour is described in more detail in the use case narratives named in the last column.

## Notes

- **The scheduler must be running.** Items 1, 5 and 9 only run if `php artisan schedule:run` is called every minute from a cron entry (or a worker) on the host.
- **The seeded fines are indicative.** Overcharging (₱5,000 / 10,000 / 15,000), colorum 1st offense (₱50,000) and the franchise-condition tiers follow LTFRB/DOTr-LTO Joint Administrative Order 2014-01. Sources disagree on the other amounts, so check them against current LTFRB/LTO issuances. The Driver Manager can edit any of them under Violation Codes.
- **Seeding the codes is destructive.** Running `ViolationCodeSeeder` removes every existing violation code, and the violation logs that belong to them.
- **Auto-closed hours are an estimate.** Nobody knows when the driver really stopped, so the entry carries the credited regular shift. "Mark reviewed" only acknowledges it; hours can't be edited yet.
- **The inactivity check never suspends a driver who has not been warned.** A driver found already past a week with no warning on file gets the warning first and is suspended on a later run. Set `HR_EMAIL` so the warning names an address; without it the email just says "HR". An admin or Driver Manager reactivating a driver restarts their inactivity clock.
- **Maintenance km alerts use logged readings.** There is no live odometer, so a vehicle's current reading is the highest odometer logged for any of its services. Tasks with no interval are never due.
