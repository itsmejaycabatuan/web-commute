 HOW TO USE THIS CHECKLIST

   - Work through your part top to bottom. Tick a box by changing [ ] to [x].
   - If a step FAILS, change it to [F] and write what you saw on the "Notes" line (or on the line below).
   - If a step cannot be tested, change it to [-] and say why.
   - Every use case has three groups:  MAIN FLOW (happy path), ALTERNATE FLOWS (A1, A2...),
     and EXCEPTIONS (E1, E2... = what happens when something goes wrong).
   - The text after "->" is the EXPECTED result. Messages in quotes should match what the screen shows.
   - Finish each use case with the RESULT line: tick PASS only if every step above it is [x] or [-].
   - (*) marks a step that needs a fault to be forced (database down, mail server down, payment gateway
     down, lost network). Do not break the server just for this - mark it [-] unless a developer
     has staged the fault. Network loss can be simulated with the browser dev-tools "Offline" switch.
   - "Known Gaps" in the UCN files are NOT bugs - they are documented limitations. Do not log them.
   - Toasts (bottom-right) are how success and error messages appear. In add/edit/delete modals a
     validation error keeps the modal open and shows the message under its own input.

 UCN_SC_E012 - MANAGE DRIVERS                          Actor: Driver Manager / Admin   File: UCN_SC_E012_Manage_Drivers.md
==============================================================================================

 MAIN FLOW
 [ ] 1. Click "PUJ Drivers" / "Drivers" in the sidebar -> the driver management page.
 [ ] 2. -> Table with #, Driver, Status, Registered, License, Actions; a search box; status chips
        (All / Pending / Approved / Rejected / Suspended); License Expiring / Expired chips; "Add Driver".
        10 per page.

 ALTERNATE FLOWS
 [ ] A1. Add Driver: modal with Name, Email, Password, Confirm, License Number, License Code, Expiration
         Date, Contact Info, License Image. NO driver-code field. Fill all, "Create Driver" -> driver is
         created already approved, with a generated DRV-###### code; confirmation toast.
 [ ] A2. Edit (pencil): form shows the driver code read-only and the stored licence image. Change fields,
         optionally replace the image, "Save Changes" -> "Driver updated." There is NO edit icon on a
         PENDING driver.
 [ ] A3. Delete (bin): "Delete Driver?" dialog -> confirm -> "Driver removed." (try dante.cruz@, who has no
         vehicle). A driver with payments/top-ups is anonymised instead.
 [ ] A4. View (ID-card icon): read-only modal with identity, licence data and expiry; it has an "Edit" shortcut.
         The License column shows Valid / "Expires in N days" (30 or fewer) / Expired; the chips filter by it.
 [ ] A5. Suspend / Reactivate (only for an APPROVED driver): confirmation dialog with optional Reason.
         Suspend liza.mercado@ -> "Driver suspended.", she cannot log in or clock in, and her vehicle is
         released. Reactivate -> "Driver reactivated." and status is back to inactive.
         While suspended, a driver already signed in is signed out on the next click.
 [ ] A6. Pending drivers (elena.torres@, mark.ocampo@, or the one from E022) show a "Review" button.
         Approve -> licence fields required (unique number, code, expiry), a driver code is assigned,
         "Driver approved..." and they can now log in. Reject -> they cannot log in and see the rejected message.

 EXCEPTIONS
 [ ] E1. (*) Offline / service unreachable -> action cancelled with a connection notice.
 [ ] E2. Licence number already used (e.g. N01-23-000001) -> "The license number has already been taken."
 [ ] E3. Empty required fields -> offending fields listed; nothing written.
 [ ] E4. (*) Database failure -> operation cancelled and notified.
 [ ] E5. Email already registered -> rejected on the email field.
 [ ] E6. Password under 8 characters or mismatched confirmation -> rejected; no account created.
 [ ] E7. Licence image that is a PDF or over 2 MB -> rejected.
 [ ] E8. Delete a driver who still has a vehicle (ramon.delacruz@) -> a lock replaces the delete icon, and a
         forced request gives "This driver is still assigned to a vehicle. Unassign the vehicle first."
 [ ] E9. Approve an already-approved driver / reject an already-rejected one -> "This driver is already
         approved." / "...already rejected."

 Use: drivermanager@gmail.com. (E014 covers the same Violation Codes page from the UI side; do the

 MAIN FLOW
 [ ] 1. Open "Violation Codes" in the sidebar (/driver-manager/violation-codes) -> list of codes.
 [ ] 2. -> Table: Code, Violation Name, 1st / 2nd / 3rd / 4th+ Offense (P), Actions (Edit / Delete). 6 codes
        are seeded.
 [ ] 3. Add a new code (Code, Name, four fines) -> created and listed with a success message.

 ALTERNATE FLOWS
 [ ] A1. Logged out, open the page or submit add/edit/delete -> redirected to /login.
 [ ] A2. Logged in as admin, driver, commuter or maintenance manager, open the URL -> HTTP 403 "Unauthorized."
 [ ] A3. Submit with a missing field, a duplicate code, or a non-numeric fine -> back to the form with
         field messages (e.g. "The code has already been taken.", "The first offense field must be a number.")
         and the entered values kept.
 [ ] A4. Delete a code that violation logs use -> "This violation code is in use by existing violation logs
         and cannot be deleted."; code remains.
 [ ] A5. (*) Database error on add/edit/delete -> "An error occurred while processing the violation code.
         Please try again later."; nothing changed.

 EXCEPTIONS
 [ ] E1. Edit or delete a code id that does not exist -> "Error no violation code found."
 [ ] E2. Add or edit with a code that already exists (editing keeps its own code fine) -> "The code has
         already been taken."
 [ ] E3. Blank field, or a negative / non-numeric fine -> per-field validation messages.
 [ ] E4. Delete an in-use code -> blocked (same as A4).
 [ ] E5. (*) Database failure -> generic error message.
